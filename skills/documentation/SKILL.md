# Documentation skill

Use this guidance before editing Markdown in this repository.

1. State the reader’s outcome before explaining configuration details.
2. Prefer a complete, runnable command over fragments that require guessing.
3. Match code examples to the implementation you inspected.
4. Explain what a command verifies and what success looks like.
5. Keep troubleshooting short, actionable, and close to the relevant step.
6. Do not invent support claims, benchmark results, or product behavior.
7. Finish each task with the files changed, checks run, and remaining uncertainty.
